# DODO delivery roadmap — three implementation jobs, no repeated phase gates
All stages are dependency ordered inside each job. Continue automatically on reversible changes. Stop only on genuine blockers or approval-required operations; complete unrelated work.

## Job 1 — Core school ERP + finance + HR + backend
School/branch/session/terms; secure account onboarding; nine initial role experiences and fine-grained grants; reception; students; online admissions; classes, subjects, timetable, teacher assignment; attendance and QR; exams, grades, both CBSE menu groups sharing one exam engine; fee master/types/groups/discounts, invoices, receipts, bank accounts, balances; income/expense, chart of accounts, double-entry journals, immutable posted transactions, reversals, reporting; staff profiles, attendance, leave, payroll and evaluation; audit logs, documents, safe bulk import/export and branch transfer. Complete real role-based web/mobile paths for every included workflow. Test SQL + web + mobile end-to-end.

## Job 2 — LMS + school operations + portals + communication
Courses, lessons, downloads, question bank, timed tests, accommodations, server-side checks, homework, submissions, gradebook, live sessions, teacher/student/parent portal; library, transport, hostel, inventory, behavior, certificates and printable cards; alumni, calendar, continuity services, internal messages, announcements, public CMS and admissions; provider adapters for email/SMS/WhatsApp/live classes. Support Arabic/English and low bandwidth. No fake provider responses. Complete backend, clients, permissions and tests per workflow.

## Job 3 — Full inventory closure + production hardening and release
Resolve every remaining item in the 147-row matrix, cover settings, user management, branding, localization, currencies, permissions, module toggles, custom fields, file types, print and public CMS, backups and restore rehearsal, release/update strategy; full role/security and workflow testing, accessibility, reporting, performance, cross-client consistency, backup/restore and deployment instructions, Android APK/AAB and iOS archive when authorized signing/macOS available. Production migration/deployment/store submission requires separate explicit approval. No production claims from source-only checks.

## Initial scope disclosure
The seed archive is a pilot foundation, not completion of Job 1. Its SQL and client source need build and integration verification. The source inventory is not proof of functioning screens. No tenant data or account is seeded automatically.
